// ABOUT / ENGINEERING PHILOSOPHY

I'm a software engineer and technical lead with more than 14 years of experience across banking, payments, and network software. I've worked on both sides of a transaction system: C++ banking switch components and Java/Spring Boot management platforms.

My approach to architecture is pragmatic: work with the realities of existing database schemas and integration contracts, while separating reporting, scheduled processing, and other workloads when independent services offer a clear benefit.

I combine hands-on implementation with requirements analysis, database modeling, code review, and guidance for small engineering teams. I also enjoy diagnosing hard production issues and building the tooling needed to understand them.

CASE_001 / JAVA · SPRING

Banking Back-Office Architecture

A hybrid banking back-office design balancing legacy switch schemas with independently deployable reporting and scheduling services.

Read engineering notes
Challenge: Management modules depended on existing switch schemas. Approach: Keep schema-coupled functions together; separate reporting, offline workflows, and scheduling into services; transfer transaction events via Kafka. Model routing rules with multi-level JPA entities, multiple data sources, and audit events during restore. Context: At least five operational banking environments.

CASE_002 / C++ · NETWORKING

Payment Switch Modernization

Replaced pipe-based communication with socket networking to support distributed deployment, and extended the switch with bill services.

Read engineering notes
Challenge: Local pipe communication restricted module placement. Approach: Move existing modules to TCP socket messaging with ISO 8583. Add a fourth component for bill inquiry, payment and duplicate-payment prevention, connected to an external billing system. Result: Modules could be deployed across separate servers.
